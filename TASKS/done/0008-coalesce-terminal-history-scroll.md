# Coalesce terminal history scroll requests

Status: done

Dependencies: `0007-ios-safari-header-layout.md`

## Goal

Make large tmux history navigation feel responsive in the web UI, especially
for rapid mouse-wheel and single-finger touch gestures on iOS Safari, without
changing ttyd, the terminal transport, or the durable shared tmux history
model.

## Reported behavior

Scrolling through a large output such as `dmesg` is slow and continues to move
after the gesture has ended. Each small wheel or touch movement currently
starts an independent authenticated scroll request. Requests serialize on the
managed-session lock, and every request invokes multiple short-lived tmux
commands before ttyd redraws the pane. A touch gesture can therefore build a
queue of obsolete movements faster than the server can apply them.

## Material decisions

- Keep the existing `/api/sessions/{id}/scroll` contract and tmux-backed
  history. Do not replace ttyd or introduce a new terminal protocol in this
  task.
- Coalesce only high-frequency relative line scrolling generated by wheel and
  touch gestures. Preserve the exact semantics of scrollbar positioning,
  keyboard history controls, History top, and Live bottom.
- Maintain at most one in-flight relative gesture scroll request for the
  active session. While it is in flight, accumulate subsequent signed line
  deltas. Opposite directions cancel in the accumulator, and the remaining
  delta is sent promptly after the active request completes.
- Bound each emitted request to the existing UI gesture limit and continue
  draining a larger accumulated delta in bounded chunks. Do not add an
  unbounded server-side amount.
- Scope responses and queued work to the session that originated them. A
  session switch, removal, copy-mode activation, or loss of the active session
  must clear obsolete queued gesture movement and must not apply a stale
  response to the new session's scrollbar.
- A failed or aborted gesture request must release the in-flight state so a
  later gesture can scroll normally. Keep existing authentication redirect and
  error handling behavior where applicable.
- Avoid invoking `tmux copy-mode` when the initial scroll state already reports
  that the pane is in copy mode. Preserve all client-window-offset behavior,
  status-line height accounting, copy-mode exit at the live bottom, and final
  scroll-state reporting.

## Requirements

- Route iframe wheel events, parent scrollbar wheel events, and single-finger
  vertical touch movements through one shared relative-scroll coalescer.
- Keep horizontal touch gestures available for the terminal strip and keep
  browser text-copy mode from generating tmux scroll requests.
- Preserve `preventDefault` and iframe event blocking needed to avoid duplicate
  ttyd/xterm scrolling.
- Update the visible history thumb from successful responses without allowing
  an older session response to overwrite current-session state.
- Do not introduce a frontend build step or new runtime dependency.
- Do not change terminal input, resize-source modes, tmux mouse defaults,
  session lifecycle, SSH-agent forwarding, or terminal transport.

## Security and runtime boundaries

- Preserve authentication, same-origin mutation checks, managed-session
  locking, and the server-side tmux command allowlist.
- Do not log or expose terminal input or terminal output in code, tests, or
  diagnostics.
- Keep ttyd behind its private Unix socket.
- Do not restart or modify the currently deployed service as part of this
  implementation task.

## Acceptance criteria

- A rapid same-direction wheel burst received while the first scroll response
  is delayed produces one in-flight request and at most one pending request at
  a time; pending line amounts are aggregated rather than replayed as one HTTP
  request per event.
- Rapid opposite-direction inputs cancel their pending signed deltas instead of
  producing a long stale request queue.
- Releasing a multi-move vertical touch gesture does not leave an unbounded
  sequence of scroll requests, and the final applied direction and aggregate
  movement match the gesture input within scroll boundaries.
- Switching sessions while a request is delayed prevents the old response and
  queued movement from changing the newly active session's history UI.
- Copy mode and horizontal touch gestures continue to produce no relative tmux
  history scroll requests.
- After a failed relative scroll request, a subsequent wheel or touch gesture
  can issue and complete a new request.
- Repeated line-up and page-up movement while tmux is already in copy mode does
  not execute a redundant `tmux copy-mode` command. Initial entry into history,
  absolute top/set behavior, Live bottom, and client window overflow retain
  their existing results.
- Existing lifecycle, terminal interaction, resize, mobile viewport, and
  scrollbar browser tests remain green.
- `node --check internal/server/static/app.js`, `make test`, and
  `make test-browser` pass.

## Implementation summary

- Added one session-scoped signed relative-scroll accumulator shared by iframe
  wheel events, history-scrollbar wheel events, and vertical single-touch
  movement. It keeps at most one request in flight, cancels opposite pending
  deltas, and drains larger movement in chunks of at most 80 lines.
- Invalidating a gesture queue now aborts its active browser request and drops
  pending movement on session changes/removal, direct history controls, and
  copy-mode activation. Touch handlers retain their originating session, and
  scroll-state reads, direct scroll responses, and deferred scrollbar-set work
  cannot update a newly active session.
- Successful relative responses update the history thumb only while their
  originating queue and session remain current. Failed or aborted requests
  release the queue; non-success responses drop obsolete pending movement so a
  later gesture starts normally. Existing wheel/touch event cancellation and
  horizontal-touch behavior remain unchanged.
- Reused an already active tmux copy mode instead of invoking `tmux copy-mode`
  again. Added Go coverage for line-up and page-up both when entering history
  initially and when copy mode is already active; Live bottom now also avoids
  redundant entry while retaining history-bottom/cancel behavior.
- Added a delayed-response Playwright regression that verifies mixed iframe,
  parent-scrollbar, and touch input produces one initial request plus one
  aggregated request; opposite pending deltas cancel without a follow-up;
  three large touch moves drain as three bounded 80-line requests; horizontal
  touch and copy mode create no relative requests; a 502 is followed by a
  successful new gesture; and a delayed old-session response plus queued
  movement cannot update the newly selected session.
